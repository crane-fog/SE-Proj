## 声明式个人运维 Agent

### 1. 项目概述

本项目面向个人开发者、实验室服务器维护者及小型科研团队，构建一个轻量级、无目标端代理的声明式 Agentic 运维控制面。系统通过标准 SSH 连接管理多台 Linux 节点，结合 YAML 声明式状态漂移探测、基于大模型的只读根因诊断、人机协同审批、Prometheus Alertmanager 告警推送与自适应长期记忆库，降低重复运维排障成本。

技术栈：Go（Gin、SQLite）、Vue 3（TypeScript）、Prometheus

### 2. 章程

#### 2.1 业务目标

1. 效率目标：借助历史故障记忆检索与自动只读诊断，将常见重复运维故障的定位耗时降低 60% 以上。
2. 安全目标：通过独立命令安全审查、只读与变更隔离、人机协同审批及密钥脱敏中间件，保证未授权高危变更零执行。
3. 可用性目标：控制面打包为单一可执行文件，支持在 10 分钟内完成部署并纳管 3 台以上 Linux 节点。

#### 2.2 角色与权限模型

系统采用轻量级三角色权限控制：

1. Admin（管理员）：管理受管节点 SSH 凭据、配置大模型接口与自主性策略、审批并触发状态变更类修复计划、管理用户角色。
2. Operator（运维员）：查看节点状态与诊断日志、编写与修改声明式状态基线、发起交互式排障对话、提交修复建议及维护长期记忆库。
3. Viewer（只读审计员）：查看节点健康概览、漂移告警记录、诊断轨迹及历史记忆库，无权修改配置或执行远程命令。

#### 2.3 技术风险与缓解措施

1. 大模型生成高危或破坏性指令：在工具调用前设置独立命令安全审查关卡，严格区分只读与变更指令；变更指令强制挂起等待 Admin 审批。
2. 敏感凭据泄露与上下文溢出：在 SSH 输出回传大模型及落盘前，经由本地密钥脱敏中间件掩码处理，并对日志输出长度设置截断上限。
3. 外部大模型接口不可用：确定性状态漂移探测、/metrics 指标暴露与 Alertmanager 告警链路独立于大模型运行，保证基础监控与告警降级可用。

### 3. 选型论证

本项目选用增量迭代模型结合轻量级 Scrum 实践，依据如下：

1. 需求与技术边界渐进明晰：系统涉及 SSH 远程调度、大模型工具调用、命令安全审查与记忆蒸馏等多个耦合模块，大模型提示词效果与安全边界需要通过原型验证逐步收敛，适合多轮迭代演进。
2. 增量可独立交付与验证：系统天然可划分为基础设施与监控告警底座、智能诊断与安全审批闭环、自适应长期记忆三层能力。按增量交付可确保每个里程碑均有可运行系统，降低集成风险。
