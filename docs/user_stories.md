## 用户故事清单

### 基础设施、权限控制与监控告警

#### US-01 多角色登录与访问控制

- 用户故事：作为系统用户（Admin / Operator / Viewer），我想使用独立账号登录控制面并受角色权限约束，以便防止越权查看密钥或执行高危运维操作。
- 验收标准：
    - Given 用户未登录或以 Viewer 身份登录系统
    - When 尝试调用节点修改、基线编辑或命令审批接口
    - Then 系统返回 HTTP 403 拒绝访问并记录越权审计日志

#### US-02 用户角色分配与账号管理

- 用户故事：作为 Admin，我想创建、停用团队成员账号并分配 Admin、Operator 或 Viewer 角色，以便规范实验室或小团队的协作分工。
- 验收标准：
    - Given Admin 已登录账号管理页面
    - When 新增成员并分配为 Operator 角色后保存
    - Then 新成员仅可执行基线维护与诊断查询，无法访问 LLM API 密钥配置页面

#### US-03 受管 Linux 节点注册与凭据加密存储

- 用户故事：作为 Admin，我想在控制面录入目标 Linux 节点的主机地址、端口、用户名与 SSH 私钥，以便在不安装目标端代理的前提下纳管服务器。
- 验收标准：
    - Given Admin 在节点管理表单填写有效的 SSH 连接参数与私钥
    - When 提交保存节点信息
    - Then 系统使用主密钥加密私钥并存入 SQLite，数据库文件中不出现明文私钥

#### US-04 节点 SSH 连通性测试与下线移除

- 用户故事：作为 Admin，我想一键测试节点 SSH 连通性并支持移除已下线主机，以便及时清理无效资产。
- 验收标准：
    - Given 控制面已存在一个注册节点
    - When Admin 点击连通性测试按钮
    - Then 系统在 5 秒内完成 SSH 握手并返回节点主机名与系统版本，或返回明确超时/认证失败原因

#### US-05 声明式期望状态 YAML 基线编写与校验

- 用户故事：作为 Operator，我想通过表单或 YAML 编辑器定义节点期望状态（如服务存活、容器状态、磁盘阈值）并附带自然语言运维意图，以便统一描述运维标准。
- 验收标准：
    - Given Operator 编写了一份包含语法错误或缺失必填字段的 YAML 基线
    - When 点击保存或校验按钮
    - Then 系统阻断保存并在界面高亮提示具体错误行与字段说明

#### US-06 状态基线试运行与启用调度

- 用户故事：作为 Operator，我想在正式启用基线前执行一次试运行探测，以便确认基线规则与目标节点当前状态匹配。
- 验收标准：
    - Given 一份语法校验通过的草稿状态基线
    - When Operator 点击试运行并确认激活
    - Then 系统立即执行一次比对并展示期望值与实际值差异，激活后基线状态变为 Active 并加入定时调度

#### US-07 周期性自动状态漂移探测

- 用户故事：作为系统调度器，我想按配置周期自动对 Active 基线对应的节点执行轻量级只读 SSH 探测，以便在零人工干预下发现状态漂移。
- 验收标准：
    - Given 节点配置了 60 秒探测周期的 Active 基线，且目标容器意外停止
    - When 调度周期到达并完成 SSH 探测
    - Then 系统在 2 秒内完成单节点探测、判定状态漂移并生成一条状态为 Open 的故障事件

#### US-08 节点健康概览与实时漂移状态查看

- 用户故事：作为 Viewer，我想在首页总览面板查看所有节点的在线状态、资源摘要与当前告警事件，以便随时掌握集群健康状况。
- 验收标准：
    - Given Viewer 登录 Web 控制台
    - When 进入节点健康概览页
    - Then 页面展示受管节点总数、健康节点数、漂移事件列表，且所有修改与审批操作按钮处于隐藏或禁用状态

#### US-09 Prometheus /metrics 指标接口暴露

- 用户故事：作为系统监控组件，我想在控制面暴露标准的 /metrics 接口输出节点在线数、探测耗时、漂移次数与大模型调用耗时，以便接入 Prometheus 进行持续监控。
- 验收标准：
    - Given 控制面处于运行状态
    - When Prometheus 定时抓取控制面的 /metrics 端点
    - Then 端点返回 HTTP 200 及符合 OpenMetrics/Prometheus 文本格式的节点健康与漂移指标

#### US-10 Alertmanager 异常告警与外部消息推送

- 用户故事：作为 Admin，我想通过 Prometheus Alertmanager 将状态漂移及待审批事件推送至外部消息渠道（如 Webhook/飞书/钉钉/邮件），以便在异常发生时第一时间获知。
- 验收标准：
    - Given 节点发生持续状态漂移且触发 Prometheus 告警规则
    - When 告警状态进入 Firing 并送达 Alertmanager
    - Then 外部消息接收端在 1 分钟内收到包含节点名、漂移摘要与控制面处理链接的推送消息

### 智能诊断、安全审查与人机协同

#### US-11 大模型接口与自主性安全策略配置

- 用户故事：作为 Admin，我想在设置页面配置 OpenAI 兼容接口地址、API Key、模型名称、最大推理轮数及脱敏规则，以便灵活切换模型并控制调用成本。
- 验收标准：
    - Given Admin 填写新的兼容模型端点与最大推理轮数（如 max_turns = 8）并保存
    - When 系统后续触发诊断推理
    - Then 请求路由至新配置的模型接口，且密钥在数据库中加密存储

#### US-12 故障触发自主只读根因诊断

- 用户故事：作为系统诊断智能体，我想在检测到状态漂移后自动检索历史记忆并调用只读诊断命令进行多轮推理，以便定位故障根因并生成修复方案。
- 验收标准：
    - Given 系统生成一条状态漂移事件
    - When 启动 ReAct 诊断循环
    - Then 智能体在不超过 max_turns 轮内完成只读排查，产出结构化根因报告与修复计划，并将事件状态置为 Pending Approval；若超轮数则置为 Escalated

#### US-13 独立命令安全审查关卡

- 用户故事：作为系统安全中间件，我想在每条 SSH 命令执行前由独立命令审查机制将其分类为只读、变更或破坏性指令，以便阻止诊断阶段擅自修改系统状态。
- 验收标准：
    - Given 诊断智能体尝试在诊断阶段调用包含 rm、systemctl restart 或混淆编码的指令
    - When 命令经过安全审查关卡
    - Then 审查关卡将其判定为非只读并立即拦截执行，同时向智能体返回禁止修改的提示

#### US-14 诊断日志与回传上下文密钥脱敏

- 用户故事：作为系统隐私中间件，我想在 SSH 命令输出发送给外部大模型或存入 SQLite 前自动掩码其中的 API Key、密码与私钥，以便防止敏感凭据泄露。
- 验收标准：
    - Given 远程节点返回的日志文本中包含标准格式的 API Key、Bearer Token 或密码字段
    - When 日志经过脱敏中间件处理
    - Then 所有匹配凭据均被替换为 [REDACTED_SECRET]，且明文凭据不出现在外发请求与数据库记录中

#### US-15 修复计划人机协同审批与执行验证

- 用户故事：作为 Admin，我想在审批界面审阅诊断证据与拟执行的变更命令，并在确认或微调参数后批准执行，以便在可控前提下恢复服务。
- 验收标准：
    - Given 故障事件处于 Pending Approval 状态
    - When Admin 点击批准执行按钮
    - Then 系统通过 SSH 执行已批准命令，并自动重跑一次声明式状态探测；探测通过后事件状态流转为 Resolved

#### US-16 修复方案驳回与交互式排障对话

- 用户故事：作为 Operator，我想在自然语言对话窗口向智能体追问节点异常，或在发现修复计划不合理时附带约束条件驳回重规划，以便实现高效人机协作。
- 验收标准：
    - Given Operator 对当前修复方案不满意并输入约束反馈后点击驳回
    - When 智能体接收到反馈并重新规划
    - Then 智能体基于新的约束条件生成修订后的修复方案并重新提交审批；对话中的只读查询同样受安全审查约束

### 自适应长期记忆与非功能保障

#### US-17 已解决故障的自适应长期记忆蒸馏

- 用户故事：作为系统记忆管理模块，我想在故障流转为 Resolved 后自动将脱敏后的排障过程与有效修复步骤压缩为结构化记忆记录，以便长期沉淀运维经验。
- 验收标准：
    - Given 一个故障事件通过审批执行或人工修复并标记为 Resolved
    - When 触发记忆蒸馏流程
    - Then 系统生成包含症状关键词、根因、修复步骤与适用范围标签的结构化记忆卡片，并展示给 Operator 确认保留或丢弃

#### US-18 长期记忆检索、版本更新与日常维护

- 用户故事：作为 Operator，我想按关键词检索历史运维记忆，并在方案演进后更新旧记忆版本或归档一次性偶发记录，以便保持记忆库的高准确率。
- 验收标准：
    - Given 记忆库中已存在历史同类故障记录
    - When 新故障命中旧记忆且修复步骤经人工修改后验证有效
    - Then 系统插入新版本记忆并将旧记录标记为 Superseded；若未修改则递增原记录命中计数 hit_count

#### US-19 [NFR] 多节点周期探测与诊断响应性能约束

- 用户故事：作为系统性能保障基准，我想控制面在同时监控 20 台 Linux 节点且探测间隔为 60 秒时保持低资源占用与稳定响应，以便满足个人及小型服务器单机部署要求。
- 验收标准：
    - Given 控制面在 4 vCPU 主机上以 60 秒间隔连续探测 20 台测试节点
    - When 持续运行 30 分钟压测监控
    - Then 控制面进程内存占用低于 300 MB，空闲态 CPU 占用低于 10%，单节点 SSH 探测耗时小于 2 秒，端到端多轮诊断耗时不超过 120 秒

#### US-20 [NFR] 大模型接口故障降级与安全零越权合规

- 用户故事：作为系统可靠性与安全合规保障，我想在外部大模型接口超时或不可用时保持基础探测与告警正常运作，并保证任何破坏性指令均被硬拦截。
- 验收标准：
    - Given 外部大模型接口返回 503 错误或网络断开，同时基线探测发现节点状态漂移
    - When 调度器执行定期巡检
    - Then 漂移探测、故障记录、/metrics 指标更新与 Alertmanager 告警推送均正常执行不受阻断；且安全审查对破坏性命令（如 rm -rf /、mkfs）的拦截率为 100%
